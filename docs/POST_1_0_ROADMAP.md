# ASP Classic Language Support после 1.0

Этот документ намеренно отделяет развитие продукта от release blockers версии
`1.0`. Перечисленные возможности полезны, но не должны задерживать стабильный
первый выпуск или расширять его риск на финальном этапе.

## 1.1 — развитие анализа кода

- Inspection неиспользуемых `Dim` и `Const` после отдельного аудита ложных
  срабатываний в динамическом ASP/include-коде.
- Default members в сокращённых COM-цепочках, например
  `rs.Fields("Name").Value` без явного `.Item`.
- Вывод типа объектов, присвоенных в include-файле и используемых в
  подключающем ASP-файле.
- Вывод пользовательских классов через промежуточные переменные, условные
  ветви и более сложные return-цепочки.
- Обобщённый nested `With` для документированных COM/member-return цепочек.
- Quick Documentation для документированных COM-членов: сигнатура,
  возвращаемый тип и краткое описание.
- Project-wide stub/index для `Sub`, `Function`, `Const`, `Class` и `Property`
  вне include-графа.
- Заменить три deprecated-вызова `ReadAction.compute(ThrowableComputable)`,
  сохранив совместимость с минимальной платформой 262.

## 1.2 — расширение платформы ASP Classic

- Поддержка `global.asa`, server-side `<script runat="server">` и обработчиков
  `Application_OnStart`, `Application_OnEnd`, `Session_OnStart`,
  `Session_OnEnd`.
- Дополнительные COM-каталоги: CDO, ADSI, `WScript.Shell`, старые компоненты
  IIS и осторожно документированная Office Automation.
- `<OBJECT RUNAT="Server" PROGID="...">` как источник типа.
- Пользовательские декларации типов и членов для проектных COM-компонентов без
  угадывания их API плагином.
- Дополнительные enum ranking и insert handlers для вызовов с параметрами.

## Долгосрочный backlog

- Явная конфигурация нестандартного virtual web root/content roots для include.
- Отдельно спроектированное форматирование ASP внутри сложных quoted HTML-
  атрибутов. До этого formatter сохраняет такие границы и не перестраивает их.
- Дополнительные WYSIWYG/legacy HTML fixtures и редкие конструкции parser-а.
- Поддержка более широкого диапазона IDE после появления проверенной матрицы
  совместимости; `1.0` не обещает неподтверждённые платформы.
- Новые inspections только при линейной стоимости и подтверждённо низком числе
  ложных срабатываний на реальных проектах.

## Сознательно вне плана

- Встроенный VBScript/ASP debugger и интеграция с Windows Script Debugger/PDM.
- Попытка статически угадать API неизвестных проектных COM-компонентов.
- Автоматическое «исправление» заведомо повреждённых или архивных файлов ради
  нулевого числа parser diagnostics.
